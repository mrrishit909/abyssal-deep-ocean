# ABYSSAL: deep-ocean exploration and submersible intelligence

A Blender-to-web build: the descent opens on a black screen and a sonar ping, falls through 4,200 m, finds a structure in the headlights, and the widening light becomes the mask through which **Mission Control** appears. Then you pick a dive, scrub it, watch sonar reveal the seabed, open observations that sit in the terrain, and turn the vehicle in the fleet view.

Built from blueprint 01 of the *Advanced Engineering Build Book, Volume VII* as a **vertical slice**. **Everything is synthetic**: expeditions, vessels, vehicles, telemetry, species and the hidden structure are generated by `data/simulators/generate.ts`; the seabed is a deterministic noise function. Nothing is a real survey.

- Live: https://mrrishit909.github.io/projects/abyssal-deep-ocean/demo/
- Case study: https://mrrishit909.github.io/projects/abyssal-deep-ocean/

## Run it

```bash
npm ci
npm run seed                      # regenerate the synthetic dataset
npm run model                     # Blender 4.5: build.py then validate.py (GLBs are committed, so optional)
npm test                          # 24 domain + API tests
npm run build && node scripts/serve.ts 8631    # static export on http://127.0.0.1:8631
npm run e2e                       # 18 Playwright tests (needs Google Chrome)
node apps/api/src/server.ts       # the /v1 API on :8630 (OpenAPI at /openapi.json)
```

`?skip=1` skips the intro, `?view=replay|sonar|species|fleet|archive`, `&dive=dive-03`, `&t=6000` (seconds), `?gfx=off` forces the poster fallback, `?motion=reduced` forces reduced motion.

## The pipeline

1. `model/build.py` (Blender, headless) builds the submersible and the seabed kit with stable node names and unit-scale pivots, exports GLBs, saves `source.blend` and renders `renders/poster.png`.
2. `model/validate.py` re-imports the GLBs into a fresh scene and fails on missing nodes, orphans, bad pivots or a budget breach.
3. The browser owns motion: thruster props, arm sway, sonar array, lamp cones, fog, particles and the terrain shader's sonar reveal are all runtime. Blender physics and lighting are not assumed to transfer.

## Agent roles

`.claude/agents/` defines the twelve roles from the book (creative-director, system-architect, repo-explorer, blender-artist, webgl-engineer, motion-director, frontend-engineer, backend-engineer, routine-worker, qa-engineer, performance-engineer, final-reviewer), `.claude/skills/` the six project skills, and `.claude/settings.json` a post-edit hook that reminds you to rebuild the asset. **Honest note:** this repository was produced in one Claude Code session that played those roles in sequence on one working tree, not by parallel subagents in separate worktrees. The multi-agent workflow is the development process only; the product contains no agents.

## Not built, and why

PostGIS/TimescaleDB (the demo reads JSON; the book's schema is the target), MapLibre/deck.gl, FastAPI (Node is used, same contract), object storage, KTX2/Meshopt (assets are small), auth, OpenTelemetry, a recorded demo video, a measured result on a physical GPU (see the performance report), touch testing on a real phone, and a skinned/animated Blender model (the browser animates named pivots instead).
